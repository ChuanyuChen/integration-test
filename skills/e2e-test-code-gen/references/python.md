# Python Profile (pytest)

Applicable repositories: `registry-center`, `orchestration-center`, `a2a-t-sdk-python`, `workflow-engine-sdk-python`

## Tech stack

- Test framework: **pytest** + **pytest-asyncio** (A2A-T / registry / orchestration are all async services — async test cases must use this plugin)
- HTTP test client: **httpx** (the ASGI transport can talk directly to a FastAPI app for in-process integration tests — no need to start a service)
- Mocking: pytest built-in `monkeypatch` + `unittest.mock.AsyncMock`
- Coverage: **pytest-cov**, threshold 80%
- Environment/dependency management: **uv** (reuse the target repo's `pyproject.toml`; do not create new dependency-management files)

## Directory structure conventions

E2E test code goes into the repo-root `e2e/<feature>/` (test-plan §11, `<feature>` from the CSV Module column); in-repo layered unit/integration tests follow the existing `tests/` convention:

```text
e2e/<feature>/                     # E2E test code (landing point generated by this skill)
├── conftest.py              # Directory-level fixtures: clients, service-readiness polling
├── test_<feature>_<scenario>.py
tests/
├── unit/                    # Pure-function and single-class tests (no I/O)
└── integration/             # In-process integration tests (httpx ASGI transport)
```

## Naming and markers

- Files: `e2e/<feature>/test_<feature>_<scenario>.py`; test cases: `test_<action>_<expected_outcome>`
- The case ID goes on the first line of the docstring (without brackets), e.g. `"""FIT-registry-center-agentcard-001: register a valid agent successfully"""`

## Labels (test-plan §5.3, mandatory)

Every test case must carry the `feature` / `environment` / `components` / `priority` / `execution` (smoke|full|slow) / `skip` (a temporary skip must comment the related issue) labels, plus the Case ID label and the Milestone label. Implement with pytest custom marks:

```python
# pytest.ini / pyproject.toml must register the markers first:
# [tool.pytest.ini_options]
# markers = [
#     "feature(name)",
#     "environment(name)",
#     "components(names)",
#     "priority(level)",
#     "execution(level)",
#     "case_id(id)",
#     "milestone(id)",
# ]

@pytest.mark.feature("registry-center")
@pytest.mark.environment("docker-compose")
@pytest.mark.components("registry-center,mockagent")
@pytest.mark.priority("P0")
@pytest.mark.execution("smoke")
@pytest.mark.case_id("FIT-registry-center-agentcard-001")
@pytest.mark.milestone("26-winter")
async def test_register_agent_success(client):
    """FIT-registry-center-agentcard-001: register a valid agent successfully"""
    resp = await client.post("/v1/agents", json={"name": "fault-mgmt-agent"})
    assert resp.status_code == 201
```

- Temporary skip: `@pytest.mark.skip(reason="blocked by https://github.com/project-openan/registry-center/issues/123")` (built-in pytest mark, no registration needed; the reason must contain the issue link); to filter a single case: `pytest e2e/<feature>/ -k "FIT_registry_center_agentcard_001"` (`-k` matches the case ID in the docstring; marker values containing hyphens cannot be used in `-m` expressions)

## Key patterns

```python
# conftest.py provides an in-process client (default approach for the integration layer)
import httpx
import pytest

@pytest.fixture
async def client(monkeypatch):
    monkeypatch.setenv("REGISTRY_STORE", ":memory:")
    from registry_center.app import create_app
    transport = httpx.ASGITransport(app=create_app())
    async with httpx.AsyncClient(transport=transport, base_url="http://test") as c:
        yield c
```

```python
# async test case
@pytest.mark.asyncio
async def test_register_agent_success(client):
    """FIT-registry-center-agentcard-001: register a valid agent successfully"""
    resp = await client.post("/v1/agents", json={"name": "fault-mgmt-agent"})
    assert resp.status_code == 201
```

- The e2e layer connects to a running service via the `REGISTRY_CENTER_URL` environment variable (from the repo-root `e2e/.env.template`); skip condition: `pytest.mark.skipif(not os.getenv("REGISTRY_CENTER_URL"), ...)`; never commit `.env` to git (add it to `.gitignore`)
- Data-driven testing: `@pytest.mark.parametrize`, with data in `tests/assets/`
- For waiting/synchronization use framework retries (tenacity) or poll the health endpoint — sleeps are forbidden; test cases must be independently rerunnable — no inter-test ordering dependencies or shared mutable state; every `see result N` must have an explicit assertion — log-only is forbidden; teardown cleans up after the fixture `yield`, deleting all resources created by the case; session-scoped fixtures are limited to read-only config (LLM config, login state); for LLM/generative output use deterministic assertions (status codes/structure/state/sort fields) — never assert on generated text

## Run commands

```bash
uv run pytest e2e/<feature>/ -q                    # full run
uv run pytest e2e/<feature>/ -m "not slow"         # local self-check (fast subset, or -m smoke)
uv run pytest e2e/<feature>/ -m execution          # filter by execution strategy
uv run pytest --cov=src --cov-fail-under=80        # with coverage
```

## Minimal validation after generation

```bash
uv run pytest --collect-only -q   # everything must be discoverable
uv run ruff check e2e/<feature>/  # lint passes
```
